# 先读这里：首次安装与测试

这是0.4.0软件验证版，需要一部Android手机及已按接线图连接的XIAO/载板。APK可直接安装，不需要你开发或上架App。首次安装、授权及固件烧录由子女或装配人员完成。

## 1. 给挂件烧录固件

1. 若已装壳，打开后盖使用XIAO原本的USB口；后置充电口没有数据线，不能用于烧录。编程前拔掉后置口的充电线，两口不可同时供电。
2. 用可传数据的USB线连接XIAO与电脑，快速双击板上的RESET小按钮，进入引导模式。
3. 如果电脑出现BOOT磁盘，查看其中INFO_UF2.TXT，确认是XIAO nRF52840基础版及S140 7.3.0兼容环境，然后把本包的 `radio-reminder-xiao-nrf52840.uf2` 拖入该磁盘；复制完成后挂件会重启。
4. 本固件是应用程序，不替换引导程序或SoftDevice。若没有BOOT磁盘、版本不匹配或文件复制后没有启动，请把显示信息交给设计助手继续处理。本包另含串口DFU备选包，不要自行擦除整片Flash。
5. 新手机配对窗口为开机后60秒；超时可长按前面换音键3秒重新开启60秒。首次测试从最低音量开始。

## 2. 手机安装

1. 把本包的 `radio-reminder-validation.apk` 传到手机，打开安装。Android可能要求允许当前文件管理器安装未知应用，按系统提示对该安装来源授权。
2. 应用名为“收音机提醒·验证版”。打开后按页面顺序授予电话、附近设备及通知权限；Android 8–11蓝牙扫描还需要定位授权与系统定位开关。
3. 点“允许读取系统未接通知”，在系统通知读取列表中启用本应用。Android 13及以上若提示“受限设置”，在本应用的系统应用信息页检查是否提供“允许受限设置”，确认是本项目安装包后再授权；不同品牌入口可能不同。受系统或组织策略禁止时，请反馈手机型号与提示内容。
4. 可以尝试“可选：授权通话记录，核验未接/拒接”。这是Android受限制的权限，系统可能不给授权，反复点授权不会解决安装渠道的限制。
5. 有通话记录权限时自动使用严格核验模式；没有时，默认不自动计数。若要继续真实来电试验，可明确打开“启用通知兼容模式（可能误计拒接）”。该路径不保证区分主动拒接。
6. 点“查找附近挂件”，选择自己手边的收音机，确认系统配对提示，等待“挂件已连接”和时间有效。一次只开启一个待配对挂件。
7. 点一次“开始来电监听”启用监听与自动恢复；保留运行通知。小米可点“打开小米自启动设置”，允许本应用自启动，并保持后台无限制。系统强行停止、厂商屏蔽唤起时仍需手动打开App，不保证清理后自动恢复。

## 3. 先做五分钟链路试验

白天06:00–22:00进行。

| 操作 | 预期 |
| --- | --- |
| 点“试听一次” | 挂件播放一次短提示 |
| 待机时按前面下方三角换音键 | 两种提示音切换并试听 |
| 按顶部音量± | 在低/中/高三档饱和调整 |
| 将手机设为静音，点“模拟一通漏接”两次 | 不启动重复提醒 |
| 第三次模拟 | 启动每10秒一轮提示，至多2分钟 |
| 提醒中短按前面下方三角换音键 | 立即停止、计数清零，不切换音色 |
| 再模拟三次，点“我已查看手机” | 停止提醒 |
| 模拟提醒后关闭手机蓝牙 | 挂件停止；重连不补响 |
| 长按电源2秒后松开，再持续按2秒开机 | 关机/唤醒；重连后重新同步时间 |

模拟仍受手机静音/勿扰与夜间规则约束。模拟期间真实漏接不混入测试计数；完成后点“清空计数与停止提醒”恢复真实监听。模拟通过不代表系统来电识别已经通过。

## 4. 再测真实电话

退出模拟并清零，手机保持静音，服务与挂件保持连接。用另一部手机在10分钟内拨3通，每通等它自然结束，勿手动拒接。检查前2通不提醒、第3通结束后提醒。然后分别测试前面单键停止、接听/回拨、点击系统未接通知能否停止。

主动拒接必须单独试：严格模式应显示拒接且不增加计数；兼容模式若系统发出未接通知，可能误计，需要记录品牌、系统版本和运行记录。只亮屏/解锁不会被当成已查看，未经过通知的查看请使用App的停止操作或提醒中短按前面单键。

夜间22:00–06:00应不发声；无时钟同步时应无声；06:00不集中补响。不要把“模拟通过”记录为“真实电话通过”。

## 6. 0.4.0 覆盖安装与恢复测试
APK与旧版同包名和签名，覆盖安装，不卸载、不清数据；数据库沿用版本2，0.3.0数据库自动迁移并保留记录。固件为0.2.0，不重刷。旧版用户先点一次“开始来电监听”，确认首页“自动恢复：已启用”。未点过的默认关闭，不会擅自后台启动。
小米MIX 2S/MIUI12.5已设无限制仍失败，现加入代码恢复后需重新实测。点“打开小米自启动设置”允许本应用自启动；该入口无法打开时回到应用信息查找，并反馈实际菜单。记录准确Android版本、是否自启动/后台锁定以及每次清理的方式，不能仅凭MIUI版本推定系统API。

### 先测历史和主动停止
1. 开启监听，接听/自然未接/拒接各一通；按日期查看时间、结果、实时/补读来源、首次保存时间。未核验不得写成已核验；一通不得因两次广播而重复计数。
2. 重开/覆盖安装后历史保留。首页显示“最近自动启动”和“最近恢复失败”，手动打开不能抹掉原有自动恢复证据。
3. 点“停止监听与自动恢复”，确认开关为未启用；随后划掉、来电、重启均不应擅自开启。再次手动点开始后才允许恢复。

### 分开测试划掉与一键清理
1. 开始监听并记下启动时间，返回桌面。先以Home/锁屏测试，再独立测试“划掉此App”和“最近任务一键清理”，每组前重新启动监听。
2. 清理后不打开App，观察运行通知能否保持或重新出现。恢复检查是非精确闹钟，可能延后；没有固定5秒恢复保证。
3. 使用另一手机拨一通普通电话并自然结束。结束后才打开App查看；出现“系统记录补读”只证明读到了通话记录，不能算实时恢复通过。查看首次保存时间是否接近响铃、本次服务启动来源和最近自动启动是否早于手动打开。
4. 对冷启动广播路径，可观察“电话状态广播唤起”的自动启动记录；须与真实电话时间一致。升级/手动打开后的启动不能混充清理后的自动恢复。
5. 单独打开通知权限关闭的情况：App应保留失败记录，但系统可能无法显示恢复提示，不能宣称已通知用户。

### 有挂件后的提醒验收
1. 不清理，先确认挂件通知为已连接，再在白天、手机静音下，10分钟内自然漏接3通，验证前2通无重复提醒、第3通提醒。
2. 清理后等待服务和蓝牙实际恢复，再测试3通新来电。若第一次来电才唤起服务且蓝牙尚未重连，该通不能追溯计数；记录为恢复断档，不算无缝通过。
3. 断档期间的旧电话、打开页面时补读的3通、恢复蓝牙前的电话，都不应引起补响。手机重启/进程重建会开启新会话并重置计数。
4. 蓝牙关闭时恢复服务应不崩溃；重新打开蓝牙后已保存挂件应尝试重连，时间同步后再测新电话。关掉挂件不会阻止手机历史查看，但不能通过挂件提醒验收。

### 重启、升级与失效边界
1. 已开启监听、允许自启动后重启手机，首次解锁后观察是否自动恢复；保持App不手动打开，再拨测试电话。记录BOOT恢复来源，未收到广播/厂商拦截算失败，不以事后打开补读算成功。
2. 监听已开启时覆盖安装新版，观察升级广播恢复；监听已关闭时覆盖安装不应自启。
3. 系统应用信息里“强行停止”后，不要求自动恢复；再次手动打开App可恢复之前开启的监听。Android13+系统前台任务管理器停止也不能承诺恢复。
4. MIUI禁止自启动、冻结进程、Android12+禁止后台启动前台服务时可能无法恢复；有回调时显示失败原因，无任何回调时只能待用户打开检查。不要以设置无限制或后台上锁就宣称彻底解决。
5. 验证停止按钮不会因延迟的恢复检查或重启广播再次开机监听；错误分支不应循环重启或刷通知。闹钟为单次非精确检查，不申请精确闹钟权限。
以上新版真机测试均尚未执行。桌面编译、79项检查和固件核心测试不能替代MIUI清理/广播投递/蓝牙联调。请回报Android版本、清理动作、首页恢复记录及该通历史的来源/首次保存时间，避免提供电话号码。
