# Android 跨品牌适配范围与测试方法（App 0.4.0）

核查日期：2026-11-10。对象为本项目0.4.0-validation（versionCode 5），固件0.2.0。本文是代码及厂商资料评估与测试方案，不是跨品牌真机通过证明。未改变APK或固件，未新增权限。

## 结论和证据等级

- 当前最低Android8.0/API26、target35，必须是支持普通蜂窝来电及BLE的Android兼容手机。Android7及以下不支持；平板即使能安装也不等于能监听普通来电。Android16及以后未完成兼容验证，不列作已确认支持。
- APK仅有Java/DEX，没有原生.so库，不受本项目原生库ABI限制；代码不依赖GMS。此事实只说明没有该项安装障碍，不代表所有CPU/ROM实际安装通过。
- 核心监听、数据库、前台服务、电话广播、开机/升级广播均为Android接口。小米专用部分只有自启动设置跳转；其他品牌无法解析时回退普通应用信息。没有OPPO、vivo、荣耀等品牌专用的保活授权或后台配置代码。
- 当前仅有79项桌面逻辑/存储/策略检查和固件核心测试、APK签名与权限集合检查。所有品牌0.4.0的安装、真实来电、清理恢复、重启、长时间锁屏与挂件音频链路均待真机测试。
- 用户已报告旧0.3.x在小米MIX 2S/MIUI12.5能记录部分电话，但划掉/一键清理后不可靠。该反馈不能迁移为0.4.0通过，也不能迁移为其他品牌通过。

不要只写“某品牌支持”。至少分别记录安装、来电识别、锁屏连续监听、划掉恢复、一键清理恢复、重启恢复、BLE端到端、历史持久化的结果。

## 权限和分发比品牌同样重要

1. READ_PHONE_STATE是检测普通电话状态的必要授权。READ_CALL_LOG是受安装器白名单约束的hard-restricted权限，某部小米上可授予，不能推断Pixel、三星或其他安装渠道也可以。[官方权限说明](https://developer.android.com/reference/android/Manifest.permission#READ_CALL_LOG)。
2. 无通话记录权限时：已接听可由状态序列观察；响铃结束不能确定是拒接还是自然未接。通知兼容模式默认关闭，明确开启后也只能标“疑似漏接”，可能误计拒接。不得把这条路径记成严格拒接区分通过。
3. 安装来源、系统安全策略、工作资料/受管设备都要记录。Android13及以后通知读取还可能遇到受限设置；按系统实际界面处理，不统一假定入口名称。不要为测试把本App改成默认拨号器或申请无关权限。
4. 海外认证Android设备还需按实际地区及安装渠道检查开发者验证规则。官方截至核查日说明2026-09-30起部分地区/参与商店开始实施，不概括成“全球所有APK一律不能装”。本项目未完成该类分发验证。[Android开发者验证](https://developer.android.com/developer-verification)。
5. 仅测试运营商普通来电，不包含微信/QQ网络电话。双卡同时来电、呼叫等待也不能从单路测试直接推定支持。

## 每台手机测试前登记

品牌、准确型号、Android/API版本、厂商系统版本与构建号、国行/海外ROM、安装渠道、App版本及APK校验值、单卡/双卡、默认拨号器、已授予权限、通知读取/兼容开关、自启动/省电/任务锁定设置、手机电量/是否充电、挂件固件与连接状态。不要登记电话号码、联系人或完整通知内容。

先以出厂常规后台设置做一轮，再只对本App开启后台允许项做一轮。不要把全局关闭安全功能、Root或更改默认拨号器作为合格前提。物理手机和拨入的另一部电话是必要条件；模拟漏接按钮、模拟器和源码检查不能替代电话/蓝牙实测。

## 通用测试流程

测试时长/重复次数为执行方案默认值，不是产品已通过的承诺。每项至少重复3轮；先不接挂件验证手机历史，再连接挂件做独立端到端验证。

| ID | 操作 | 通过证据或应记录的结果 |
| --- | --- | --- |
| C01 | 覆盖安装同签名0.4.0，完成权限，点开始监听 | 能启动、原历史保留；自动恢复已启用；记录通话记录权限是否真的可读，不只看按钮点击 |
| C02 | 正常接听、自然未接、主动拒接各一通 | 各有准确时间和结果；一通一行。权限不足时明确未知/疑似，不能强行记严格通过 |
| C03 | Home回桌面，再锁屏5分钟与30分钟后分别来电；App不先重开 | 响铃时已写入实时证据，保存时间接近来电；服务/通知持续。只补读到历史不算实时通过 |
| C04 | 单独划掉App，再来电 | 恢复通知/自动启动来源及时间；结束后才重开核对。不能把手动打开后的恢复算自动成功 |
| C05 | 单独一键清理，再来电 | 与C04分开计数。非精确恢复检查可能延后，逐次记录恢复延迟；冷来电广播唤起和预先恢复分开标 |
| C06 | 已开启时重启，首次解锁后不打开App再来电 | BOOT自动启动证据在手动打开前；原历史保留。未解锁阶段不要求启动 |
| C07 | 已开启时升级覆盖；另测已停止时覆盖 | 前者允许尝试恢复，后者应保持关闭；旧数据无丢失 |
| C08 | App内停止监听与自动恢复，再划掉/来电/重启 | 应保持关闭，这是用户停止的正确行为，不能因为没有恢复记成故障 |
| C09 | 系统强行停止；Android13+另测系统前台任务管理器停止 | 不要求绕过停止。手动打开后方可恢复已开启监听；断档必须如实记录 |
| C10 | 关闭/重新打开蓝牙、挂件离开/返回范围 | 手机服务不崩溃；重连后时间同步。断档不补响。没有挂件时此项不能记通过 |
| C11 | 白天手机静音、挂件事先已连接，10分钟内自然漏接3通 | 前2通不重复提醒，第3通后观察挂件实际声音；记录延迟。补读、拒接不能冒充合格漏接 |
| C12 | 接听/回拨、按前键停止、App确认，及重复通知 | 能停止或正确清零；重复广播/通知不能新增漏接计数；系统通话结果保持优先 |
| C13 | 夜间22–06、静音解除、无有效手机时间、断连、旧记录补读 | 分别符合静音/不补响规则；不得因为打开App而补响3通旧电话 |
| C14 | 不充电，锁屏连续运行2小时再到8小时/过夜，期间分批拨入 | 逐批记录是否实时、服务重建次数、BLE断档、电量变化。夜间声音按静音规则，不能把无声直接判监听失败 |
| C15 | 暂时撤回电话/蓝牙/通知权限，关闭兼容模式，恢复权限 | 不崩溃、不虚构结果；能显示必要的恢复提示/失败状态。通知被禁时不能保证系统提示可见 |
| C16 | 双卡、呼叫等待、运营商Wi-Fi通话等额外场景 | 独立扩展记录；在单卡基础流程通过前不声明这些场景已支持 |

### 判断“实时恢复成功”的关键

1. 不在来电前重新打开App，否则会触发手动恢复。
2. 记录外部拨入时间、手机通知变化，以及挂件发声时间；电话结束后再查看历史。
3. 看“最近自动启动”来源/时间与历史“实时检测”来源和首次保存时间；旧版未知来源不能当作新证据。
4. 自动服务重建后重新连上挂件属于有断档恢复，不是连续监听通过。若第一通电话才唤起App，蓝牙尚未就绪，这通不能补算为“挂件一直在线时的漏接”。
5. 如果唯一证据是稍后出现系统补读记录，结论只能是“历史查询成功，实时监听未证明”。

### 长时间锁屏的代码风险

手机时间通过Handler约30秒同步，固件时间租期90秒。Doze/厂商休眠可能延后App定时执行；因此要分别核对“手机收到电话”“蓝牙连接”“时间有效”“挂件发声”。手机有历史而挂件无声，并不一定是电话监听失败。本版没有常持唤醒锁或精确周期唤醒，不由源码推定长时间时间同步可靠。[Android后台蓝牙建议](https://developer.android.com/develop/connectivity/bluetooth/ble/background)。

## 结果分级与记录

可填配套《Android兼容性测试记录.csv》，每台手机、每个场景、每轮单独一行，结果只填“待测/通过/失败/有断档恢复/仅补读/不适用”。记录失败原因、退出动作和是否手动重开；手机是否充电、节电模式开关不可省略。正常与严格识别/兼容推断两种模式分别记录。

L1=安装授权通过；L2=真实来电及历史结果通过；L3=Home/锁屏持续监听通过；L4=具体划掉/清理/重启场景恢复通过；L5=挂件端到端及长时间运行通过。未完成下一级只能报告已验证的层级。App内主动停止和系统强停是边界测试，不能通过反复拉活去追求“L4通过”。

不提供品牌级永久白名单。系统大版本、系统管家/拨号器更新、App签名或安装来源变化后，需要重测相关权限、C03–C06和C11/C14。

## 后续开发重点（评估建议，未在此查询实现）

Android12+若要提高跨品牌BLE后台恢复，应优先评估CompanionDeviceManager/CompanionDeviceService的真实设备关联与存在感知路径；当前0.4.0未集成，不能声称具有该后台启动豁免。官方建议不等于必然解决厂商清理或系统强停。[Android后台蓝牙](https://developer.android.com/develop/connectivity/bluetooth/ble/background)。
